About This Document

The files in packet/Packet.html are high-fidelity design references built in HTML — not production code to ship. The task for the coding agent is to recreate these designs in the target codebase's environment (React Native, Expo, Swift, or a web stack — choose what fits) using its established patterns, libraries, and conventions. Pixel accuracy matters on spacing, color, and animation. Typography, corner radii, tap targets, and motion timing are all specified below.

Data Model (TypeScript)

// ── Program structure (loaded from local config/JSON) ─────────

interface Exercise {
  id:          string;         // e.g. "goblet", "rdl"
  name:        string;
  cue:         string;         // coaching cue shown in active session
  icon:        string;         // emoji (optional, behind toggle)
  sets:        number;
  reps:        string;         // "10" | "10 ea" | "30 s"
  unit:        'lb' | 'band' | 'bw';
  defaultLast: number | string | null; // pre-fill for first-ever session
}

interface Workout {
  id:        string;          // e.g. "p1w2A"
  packet:    number;
  week:      number;
  letter:    'A' | 'B' | 'C';
  title:     string;
  focus:     string;          // e.g. "Legs · Lateral · Rotational"
  estMin:    number;
  exercises: Exercise[];
}

interface Packet {
  id:          number;
  name:        string;         // e.g. "Foundation"
  totalWeeks:  number;
  workouts:    Workout[];      // 3 per week × N weeks
}

// ── Logged data (persisted in IndexedDB) ─────────────────────

interface SetLog {
  weight:   number | string;  // 45 | "Med" | "BW"
  reps:     number;
  unit:     string;
}

interface ExerciseLog {
  exerciseId:  string;
  exerciseName:string;
  sets:        SetLog[];
}

interface SessionLog {
  id:          string;          // uuid
  workoutId:   string;
  date:        string;          // ISO date "2026-06-09"
  startedAt:   number;          // unix ms
  finishedAt:  number;
  durationSec: number;
  exercises:   ExerciseLog[];
  totalVolume: number;          // lb lifted (weight × reps, sum)
}

// ── Calendar / schedule ───────────────────────────────────────

type DayStatus = 'done' | 'today' | 'scheduled' | 'skipped' | 'rest';

interface TrainingDay {
  date:      string;            // ISO date
  status:    DayStatus;
  workoutId: string | null;
  sessionId: string | null;    // null if not done
}

// ── User preferences (localStorage) ──────────────────────────

interface UserPrefs {
  accent:        string;        // hex — default #B2F042
  loggingMode:   'instant' | 'sheet' | 'pad';
  completionFeel:'subtle' | 'punchy' | 'bold';
  showEmoji:     boolean;
  density:       'compact' | 'regular' | 'comfy';
  roundness:     'sharp' | 'default' | 'soft';
}
06

Offline & Persistence Contract

IndexedDB (primary store)

  • sessions — all SessionLog records, keyed by id
  • program — user's packet/workout definitions (editable)
  • exerciseLastUsed — { exerciseId → { weight, reps } } for prefill

Writes immediately on set confirmation. Never wait for network. No network dependency.

localStorage

  • packet:prefs — UserPrefs JSON
  • packet:activeSession — in-progress session state (resume after crash/close)
  • packet:currentWorkoutId — which workout is "today"

Small, sync reads only. Write on every change.

Session persistence (crash recovery)

When a session is started, serialize the current set state (which sets are logged) to localStorage:packet:activeSession on every set confirmation. On app boot, if an active session record exists and the date matches today, offer to resume. On session complete or explicit abandon, clear the key.

Technical Requirements

Platform

  • Target: Progressive Web App (PWA) installable on iOS/Android home screen. Web is primary delivery; no App Store required for v1.
  • Viewport: Mobile-first, max-width 460px centered column. Letterboxed on desktop with subtle drop shadow on the shell.
  • Offline: Fully functional with no network after initial load. Service worker + Cache API for asset caching.
  • Orientation: Portrait only.
  • Safe areas: All fixed elements respect env(safe-area-inset-*).

Accessibility

  • Minimum tap target: 44×44px on all interactive elements.
  • All icon-only buttons need aria-label.
  • Color is never the sole differentiator for status (dot + color).
  • Completion animations must respect prefers-reduced-motion — show end-state immediately, skip keyframe animations.
  • Contrast: primary text on Surface-2 passes AA (white on #1E1E1E = 13.5:1).

Performance

  • Set logging interaction must feel instantaneous — no async operations in the tap handler critical path.
  • Haptic feedback via navigator.vibrate() where available (wrap in try/catch).
  • Fonts: preload Space Grotesk + Inter + JetBrains Mono from Google Fonts or self-host for offline reliability.
  • Animations use transform and opacity only — no layout-triggering properties.

Open Design Questions

  • Rest timer durations: Confirm default rest durations per exercise category (current spec: 90s compound, 60s accessory, 45s bodyweight). Should the user set a global default, or per-exercise?
  • Plate calculator: Useful for barbell lifts — input target weight, output plates per side. Could be a sheet triggered from the weight stepper. In scope for v1?
  • Program sync/backup: Are sessions stored locally only, or synced to a backend? Affects data layer significantly and offline conflict resolution strategy.
  • Multiple packets: Does the app ship with Packet 2+ pre-defined, or does a coach upload new packets? Who authors the program?
  • Skipped day handling: Can users manually mark a day as skipped, or is it inferred automatically after midnight?
  • Post-match logging timing: Should the "How was your game?" card appear before OR after the workout? Currently designed as pre-session. Some users may prefer logging game quality after lifting.
  • Readiness check opt-in: Should the readiness check be opt-in (off by default, user enables) or opt-out (on by default, user disables)? Affects first-run experience.
  • Share card implementation: html-to-image library vs Canvas API for rendering the share card. Consider font rendering fidelity on iOS.
  • Accent ink: When user picks a custom accent color, use luminance to decide text color: (r*299 + g*587 + b*114)/1000 > 140 → black ink, else white.
