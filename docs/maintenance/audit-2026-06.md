## 3. CSS

**Verdict: excellent tokens, missing the reuse layer, low (but real) token leakage.**

### What's good — keep it

- 52 design tokens, logical-property layout (`inline-size`, `inset-block-end`), density/roundness theming via `[data-*]`, container queries, reduced-motion handling. `app.css` (358 lines) is clean and maintainable.

### The problem — 8,170 lines of scoped CSS

Every component re-implements buttons, inputs, cards, sheets, steppers from raw tokens. There's no intermediate layer of shared component classes or utility primitives, so the same ~40-line button/input recipe is retyped per file. This is the bulk of the "wetness" you sensed.

### Token leakage (small but should be zero)

- Hardcoded hex in component styles instead of tokens: `#101010` (9×, = `--color-bg`), `#4ade80` (7×, = `--color-success`), plus one-off reds (`#f87171`, `#ef4444`, `#f97316`…). The `#eac` 57× hits are likely substrings inside gradients — verify, but the named-color leaks are real.
- **41** hardcoded `px` paddings/margins/gaps bypassing the `--space-*` scale.

### Proposed action

1. Introduce a thin **shared component layer** — either global classes (`.btn`, `.btn--primary`, `.field`, `.sheet-body`) in `app.css`, or small wrapper components (`Button.svelte`, `Field.svelte`). Recommend wrapper components to match the Svelte idiom.
2. Migrate the most-repeated recipes (button, input, stepper) first; measure the scoped-CSS reduction.
3. Replace hardcoded hex with tokens; replace stray `px` with `--space-*`.
4. This is the highest-leverage maintainability work after the docs.

## 4. Ternaries

**~178 ternaries total.** Per your absolute-no-exceptions rule, all go — including Svelte markup, replaced with `{#if}`, derived values, or small helper functions.

Concentration (top files):

| File                                    | Count |
| --------------------------------------- | ----- |
| `components/LogSetSheet.svelte`         | 17    |
| `db/debugSeed.ts`                       | 10    |
| `routes/calendar/+page.svelte`          | 9     |
| `components/DayActionsSheet.svelte`     | 8     |
| `lib/format.ts`                         | 6     |
| `components/DanceSessionOverlay.svelte` | 6     |
| `components/ActivityLogSheet.svelte`    | 6     |

**Pattern guidance for execution:**

- Markup display ternaries (`{isBand ? 'Band' : 'Weight'}`) → derived `const` or `{#if}` block.
- Default-value ternaries (`exercise.weightIncrement ?? 5`) — note `??` is nullish coalescing, **not** a ternary; those stay.
- Inline string suffixes (`{suffix ? \` ${suffix}\` : ''}`) → derived value computed in script with a named variable.

### Proposed action

Sweep file-by-file, top of the table down. Each replacement gets a named derived value or helper so the markup reads declaratively.
